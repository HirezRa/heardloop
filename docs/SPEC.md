# Heardloop - decisions

The full functional spec is kept outside the repo (owner's document). This file holds the decisions
the code depends on. Keep it in English and up to date.

## Decisions (current as of v0.9.6)

| Topic | Decision |
| --- | --- |
| Backend | Python 3.14 (image; `requires-python` allows 3.13–3.14), FastAPI, SQLAlchemy 2 async + asyncpg, Alembic |
| Dependencies | uv, exact pins in `pyproject.toml`, `uv.lock` committed |
| DB | PostgreSQL 17. Enums stored as text (no PG enum types). UTC `timestamptz` everywhere |
| Scheduler | Worker polls every 15 s; claims due posts with `SELECT ... FOR UPDATE SKIP LOCKED` + 5 min lease |
| Retries | 3 attempts, delays 1 / 5 / 15 min, then `failed` + owner notification |
| Crash safety | An attempt that started but never finished is NOT retried automatically: post -> `failed`, `unknown_outcome` |
| Idempotency | `posts.idempotency_key` unique per post; attempt row is saved before calling LinkedIn |
| Tokens | AES-256-GCM, record id as associated data, key from env `HEARDLOOP_TOKEN_KEY` |
| Media | Local Docker volume `/data/media`, random file names |
| Time | Stored UTC, displayed in the workspace time zone (default `UTC`; `create_owner --time-zone` sets IANA name, else host local if detectable) |
| LinkedIn MVP | Personal profile only: OpenID Connect + `w_member_social`, Posts API `/rest/posts` |
| LinkedIn app | Products: "Sign In with LinkedIn using OpenID Connect" + "Share on LinkedIn". Redirect URL `http://localhost:8380/api/v1/linkedin/callback`. Client ID/secret only in `.env` |
| LinkedIn OAuth | Owner-only (with TOTP). `state` = HMAC-signed {user, workspace, nonce, exp 10 min} + nonce in an HttpOnly cookie scoped to the callback path. No refresh tokens (not available to us): ~60-day token, reconnect reminder 7 days before |
| LinkedIn API | `LinkedIn-Version` pinned in `config.py` (override `LINKEDIN_API_VERSION`), `X-Restli-Protocol-Version: 2.0.0`. 201 + valid `x-restli-id` URN = published. Only 429/503 and connect errors are retried; timeouts, broken connections and other 5xx are `unknown_outcome` (never auto-retried, may already be posted). `commentary` is escaped for LinkedIn little-text reserved characters (hashtags kept) |
| LinkedIn API terms | Scheduled publishing kept by owner decision 2026-10-19. Documented neutrally in README ("LinkedIn's terms"), INSTALL (en/he §4.4), GUIDE §4, and the Accounts screen. Revisit if LinkedIn clarifies or contacts the project |
| Ports | web 127.0.0.1:8380 only. API and db are not published |
| API reachable only through the web container | `docker-compose.yml` has no `ports` on `api`; browsers, the dev server and scripts go through nginx. `docker-compose.dev.yml` (committed, development only) re-adds `127.0.0.1:8381:8000`. uvicorn trusts `X-Forwarded-*` only from `172.16.0.0/12` and loopback. Containers drop all capabilities (db keeps the few its entrypoint needs), set `no-new-privileges` and have a PID limit; `web` runs with a read-only root (tmpfs for `/tmp` and the nginx cache). The nginx access log writes the path without the query string (no OAuth codes or search terms in `docker logs`) |
| Language | Code, comments, docs, commits, issues: English. UI copy: `src/frontend/src/i18n.ts`. Hebrew user guides only under `docs/he/` |
| Documentation languages | English everywhere in the repo; Hebrew installation and n8n guides live only in `docs/he/` (English checker allows that prefix) |
| Versioning | Single source of truth: root `VERSION` (semver, no `v`). Mirrored in `package.json` / `pyproject.toml` (CI fails on mismatch). Git tags `vX.Y.Z`. Authenticated `GET /api/v1/version` exposes version + git sha; `update` field is owner-only. Not on public `/health` |
| Releases | `CHANGELOG.md` (Keep a Changelog). Tag push `v*.*.*` runs CI then creates a GitHub Release from that section |
| Update notice | Worker checks `api.github.com` only (every 12 h + start; `UPDATE_CHECK*`). Stores result in `app_meta.update_check`. Notifies owners (`app.update_available`) once per version; banner dismiss in `ui_prefs`. No in-app install - host scripts `scripts/update.*` after backup |
| UI preferences | Per user, `users.ui_prefs` JSONB validated by `UiPrefs`: language (null = server `UI_LANGUAGE`), date format (dmy/mdy/ymd), time format (24h/12h), text size (14-20 px base, all type in rem), theme (system/light/dark via `data-theme`), accent colour. `GET/PUT /auth/me/preferences`, returned in `/auth/me`; the app applies them on sign-in and remounts on change. Only cosmetic settings live here; server settings and secrets stay in `.env` |
| UI language | `UI_LANGUAGE` in `.env`: `en` (default, LTR) or `he` (Hebrew, RTL). Served by public `GET /api/v1/meta`; the web app sets `lang`/`dir` before the first render |
| Auth | E-mail + password, Argon2id, min 12 chars. Lock 15 min after 5 failures. Generic error for every failure |
| Sessions | Server-side table `sessions`; cookie holds a random token, DB stores SHA-256 only. Cookie name: `__Host-hl_session` when `COOKIE_SECURE=true` (Secure, Path=/, no Domain), else `hl_session`; both HttpOnly, SameSite=Lax; the old name is still read, only the new one is written, logout clears both. Idle 12 h, absolute 7 days |
| Session retention | Worker, hourly: sessions that expired more than 1 day ago are deleted |
| CSRF | Unsafe requests need `X-Requested-With: heardloop`; authenticated ones also `X-CSRF-Token` (per session) |
| Authorization | Role -> permission map in `heardloop/auth/permissions.py`; non-members get 404, members without permission 403. Last owner cannot be demoted or removed |
| Brute force | Row lock on the user during login (no counter race); password-change guesses, wrong second-factor codes and wrong passwords on the activity-log purge share the lockout (purge: 423 `account_locked` while locked, `audit.purge_denied` logged, other sessions signed out); nginx limits the password/code endpoints (`/auth/login`, `/auth/password`, `/auth/mfa/*`, the purge) to 10/min per IP; max 4 Argon2 hashes in parallel, off the event loop |
| Second factor | TOTP (RFC 6238, SHA-1, 6 digits, 30 s, +-1 step), own implementation in `security/totp.py`. Secret encrypted with TokenProtector (context `user-mfa:<id>`); replay blocked via `mfa_last_used_step`. Login = password -> short (5 min) pending session -> `/auth/mfa/verify` -> new full session (new token). Wrong codes share the lockout counter, which (for TOTP users) is cleared only after a correct second factor. Setup, new recovery codes and disable need the password |
| Key guard | `app_meta.token_key_fingerprint` (HMAC of a fixed label) is stored on first start; API and worker refuse to start with another `HEARDLOOP_TOKEN_KEY`. Shell variables must never carry the key (Compose prefers them over `.env`) |
| Startup key check | `ensure_token_key` retries 5 times (2 s apart) when the database is unreachable, then fails startup (`TokenKeyUnverifiedError`); it never continues with an unverified key |
| Publish outcome audit | Every publish outcome writes an audit row with `actor_id=None`: `post.published`, `post.publish_failed` (with `will_retry` / `next_attempt_at`), or `post.publish_gave_up` when the retry budget is exhausted. Reasons are error codes only |
| Account reconnect prompt | On `account_not_connected` / `token_expired` / `token_unreadable` / LinkedIn 401: set `linkedin_accounts.needs_reconnect_reason` + `needs_reconnect_at` (earliest wins), notify owners + connector once per 24 h (`account.reconnect_needed`). Cleared on reconnect (audit `linkedin.account_reconnected`) and disconnect. `POST .../accounts/{id}/retry-failed` (approver+) reschedules matching failed posts |
| Recovery codes | 10 one-time codes, HMAC-SHA256 with a key derived from `HEARDLOOP_TOKEN_KEY`; shown once; regenerating needs a TOTP code. A code is marked used only on the success path of the request that accepts it (login step 2, disable), in the same transaction; posting it to an endpoint that does not accept recovery codes leaves it valid |
| Validation errors | 422 responses carry only `loc`, `msg` and `type` of each error - never the submitted value (no password echo) |
| Response headers | API: nosniff, frame deny, no-referrer, `Cache-Control: no-store` (routes may override, e.g. media), CSP `default-src 'none'; frame-ancestors 'none'`, Permissions-Policy denying camera, microphone and geolocation. nginx repeats the security headers in the `/assets/` location |
| Text input | Workspace, campaign and member names, hashtags, goals, audiences and metric notes reject C0/C1 control characters (`\n` allowed only in goal, audience, note). E-mail subjects are stripped of line breaks again before sending |
| Owner rule | members/settings/accounts/audit permissions return 403 `mfa_required` until the owner turns on TOTP |
| Posts API | `/workspaces/{id}/posts`: create (draft + version 1), edit (new version; edits after review/scheduling go back to draft), submit/approve/reject, schedule (tz-aware, 1 min..365 days ahead, refused if the LinkedIn token expires first), publish-now (= schedule now), unschedule, delete (not scheduled/published) |
| Retry budget | `attempt_count` is reset per schedule; `publish_attempts.attempt_no` keeps counting. A manual retry of a failed post marks unfinished attempts `abandoned_by_user` after the UI asks the user to check LinkedIn; when approval is required, the current version must be approved (409 `approval_required`, same rule as rescheduling and `retry-failed`) |
| Media (upload) | Same endpoint for images and video: `POST /workspaces/{id}/media` raw body (no multipart), type from magic bytes, random file name `<workspace>/<hex>.<ext>` on the media volume; `GET` serves it with nosniff + sandbox CSP and `Cache-Control: private, no-cache` (Range for video), members only. Images: PNG/JPEG/GIF, max 5 MB. MP4: see Video. One image or one video per post (`post_versions.media_ids`) |
| LinkedIn images | Images API `initializeUpload` -> PUT bytes (only to an https `*.linkedin.com` upload URL) -> poll until AVAILABLE -> `content.media.id` in the post. Image errors happen before the post exists, so 429/5xx/network are retried. The image URN is cached per owner |
| Scheduling time zone | The UI sends `local_time` (wall clock); the server converts it with the workspace time zone (`zoneinfo`) and rejects times skipped or repeated by DST changes (422). Absolute `scheduled_at` with offset is still accepted |
| Post editor | Plain Unicode only, exactly what LinkedIn receives. "Formatting" swaps Latin letters/digits for Mathematical Alphanumeric look-alikes (sans bold/italic, script, mono); Hebrew has no such block and passes through unchanged. Underline/strikethrough via combining marks. Structure helpers: bullets, numbering, quote, separator, emoji, RLM. Counter counts code points; accessibility warning above 20% styled letters. Hashtag suggestions from the workspace's recent posts |
| Video | Upload via Media (75 KB-200 MB MP4; LinkedIn allows 500 MB), streamed with `StreamWriter`. Worker publish path: Videos API initializeUpload -> 4 MB parts (ETags) -> finalizeUpload -> poll until AVAILABLE (2 min first attempt, 10 min on retries with the cached URN); still-processing does not use up the retry budget (hard stop after 6 attempts); failed processing clears the cached URN. Video lease 30 min. Video and link card are mutually exclusive (LinkedIn) |
| Hashtags | `hashtags` table: saved library per workspace (max 200, unique case-insensitively, insert-or-ignore). `GET/POST/DELETE .../posts/hashtags` returns saved + recent (from the last 300 versions). Editor counts tags in the post against LinkedIn's 3-5 guidance (warning above 5); one word, letters/digits/_ plus Hebrew points |
| Links in text | LinkedIn has no anchor-text links: the toolbar's link button inserts `selected text (https://...)`; LinkedIn auto-links the address. Preview renders URLs as links. The link card (`content.article`) is the alternative for a titled card |
| Link card | `PostVersion.link_url/link_title/link_description` -> Posts API `content.article` (LinkedIn does not scrape URLs). The post image is the card thumbnail. `POST .../posts/link-preview` fetches Open Graph server-side with the webhook destination guard, 512 KB cap, HTML only, 3 redirects re-checked |
| Rescheduling | Same `POST .../schedule` on a `scheduled` post moves it in place (status unchanged, audit `post.rescheduled`). If approval is required, the current version must have an approval, otherwise 409 `approval_required` (covers approval turned on after scheduling) |
| Campaigns | CRUD for editors/approvers/owners; archived campaigns are hidden by default and take no new posts; only empty campaigns can be deleted. Changing a post's campaign is metadata and needs no new review. Goal/audience text is not copied into the audit log |
| Version history | `GET .../posts/{id}/versions` lists up to 200 newest versions (older kept, not listed) with `approved` when an Approval APPROVED points at that version. `POST .../versions/{id}/restore` creates a new version from the chosen one (missing media dropped with `warnings: ["media_missing"]`); allowed for draft/pending/approved/failed or imported live posts (not scheduled); same status rules as edit; audit `post.version_restored` with `from_version_id` |
| AI assistant | Optional, off unless `AI_BASE_URL` + `AI_MODEL` are set (startup refuses a URL without a model, user info or a query). Any OpenAI-compatible `/chat/completions` server; self-hosted (Ollama etc.) recommended because the text is sent there. `POST .../posts/assist` (posts write permission) with `action` (improve, shorten, hook, fix, hashtags, translate_en, translate_he), `text` (1-3000) and optional `tone`; returns `{text, hashtags}`, nothing stored, no audit row. One request, no redirects, response capped at 256 KB, `AI_TIMEOUT_SECONDS` (default 60); output stripped of control characters and wrapping fences/quotes, max 3000 characters; hashtags parsed with the editor's one-word rule (max 5). The post is fenced in the prompt and the system prompt says it is content, not instructions. 10 requests per minute per user, 2 concurrent per API process; errors 503 `ai_not_configured`, 429, 502 `ai_failed:<timeout/unavailable/bad_response/empty>`. Logs: action, outcome, duration only. The URL comes from `.env`, so it is not routed through the webhook SSRF guard. `/auth/me` returns `ai_assist` so the editor shows or hides it |
| Best times | `GET .../reports/best-times?days` (30-366, default 180; members): latest measurement of each published post with impressions, grouped by weekday + hour in the workspace time zone, ranked by average engagement rate; a slot needs 2 posts and nothing is suggested below 5 measured posts; at most 3 slots. No AI. The editor shows them as chips next to the scheduling field (next occurrence of that weekday/hour) |
| Templates | `post_templates` (migration 0016): text/link/tags/optional campaign, no media. Placeholders `{{name}}`/`{{date}}`/`{{campaign}}`/`{{link}}`/`{{custom}}` filled on `POST .../templates/{id}/use` (increments `use_count`, no post created). Unique active name per workspace (case-insensitive). Delete owner-only and refused when `use_count > 0` (`template_in_use` → archive). Audit `template.*` with ids/names only, never body |
| Calendar | `GET /workspaces/{id}/calendar?start&end` (dates in the workspace zone, max 62 days, max 1000 items + `truncated`). Drag-and-drop calls the schedule endpoint with the same local time on the new day; past days accept no drop |
| Notifications | Outbox rows written in the same transaction as the action: `notifications` (per user, in-app + e-mail status) and `webhook_deliveries`. Events: submitted (owners/approvers), approved/rejected (author), published (author), failed (author + owners), LinkedIn token expiring in 7 days (owners, once per expiry). | E-mail | Optional SMTP (`SMTP_*`), plain text, English, fixed subjects, no post text. One short transaction per message, 3 attempts, 60 s budget per worker cycle; `SMTP_SECURITY=none` with a login is refused at startup. Users can switch e-mail off |
| Webhook | Owner (with 2FA) sets URL; secret generated server-side, encrypted (AES-GCM, workspace context), shown once. `X-Heardloop-Signature: sha256=HMAC(secret, "<timestamp>.<body>")`. Post text, reviewer comments and the names `actor_name`/`account_name` only if `include_text` is on at send time (ids stay). Claimed with a lease, sent outside DB transactions, 15 s total deadline, body never read, no redirects, retries 1/5/15/60 min. SSRF guard at send time: everything that is not globally routable is refused (`not is_global`, IPv4-mapped IPv6 unwrapped; loopback, link-local/metadata, unspecified, multicast and reserved even for webhooks), plus the addresses of `db`, `api`, `web`, `worker` and the `APP_BASE_URL` host resolved at API/worker start (refreshed hourly in the worker); private LAN (RFC 1918, unique-local) allowed for webhooks only (n8n). The file is never stored; only numbers, aggregated audience shares (category, value, share; at most 50 rows, shown as top 3 per category), and top job title/location/industry are kept (`post_metrics.source=linkedin_export`, new nullable columns, `demographics`/`top` JSONB). | Imported posts | A post created by an analytics import (`posts.external_source` set) is `published` from the start, never re-published and never approved. Empty text is allowed for these posts only (`body_required` does not apply). | Weekly digest | Worker, hourly check: Monday 08:00+ in the workspace time zone, once per ISO week (`workspaces.last_digest_week`), skipped when there is nothing to say and not caught up later. | Backups | Compose service `backup` (`src/backup`, `postgres:17-alpine` so `pg_dump` matches `db`; non-root, read-only root, tmpfs `/tmp`, all capabilities dropped, no ports). Nightly at `BACKUP_HOUR_UTC` (sleep loop, JSON logs, clean stop on TERM) or once with `entrypoint.sh now`. One set per run, `heardloop-YYYYMMDDTHHMMSSZ`: `pg_dump --format=custom --compress=6` (read back with `pg_restore --list`), the media volume as `tar.gz` (read back with `tar -t`), `.sha256`, and a manifest `<set>.json`; `latest.json` is replaced atomically. Optional encryption with `BACKUP_PASSPHRASE`: `openssl enc -aes-256-cbc -pbkdf2 -iter 600000 -salt`, read back and compared before the plain text (kept only in tmpfs) is dropped; the SHA-256 file detects damage, not deliberate tampering (CBC has no authentication). | Settings | `GET/PATCH /workspaces/{id}/settings` (name, IANA time zone, require_approval); read for members, edit for owners |
| Audit filters | `GET .../audit` takes `category` (action prefix), `actor_id`, `since`/`until`, `q` (ILIKE over action, entity id, details JSON, actor name). Clearing: `POST .../audit/purge` (owner with 2FA, password re-entered) deletes this workspace's entries and the sign-in events of members whose only workspace this is, all or before a date; the purge is itself logged (`audit.purged`, count, cutoff). No blind DELETE. Settings screen is split into tabs (workspace, members, sign-in & security, webhook, activity log) |
| Member anonymisation | `POST /workspaces/{id}/members/{user_id}/anonymise` (owner with 2FA, body `{code}`: a TOTP or recovery code, no password). Refused for yourself, the last owner and people who belong to another workspace. One transaction: memberships, sessions, notifications and recovery codes deleted; tokens of LinkedIn accounts they connected are cleared; IP addresses in their activity-log rows are set to null; `email` = `deleted+<user id>@invalid`, `display_name` = `Former member`, password hash null, TOTP cleared, `email_notifications` false, `ui_prefs` empty, `is_active` false, `deactivated_at` set. | Media sweeper | Worker, hourly: `media_assets` older than 24 h that no `post_versions.media_ids` lists are deleted (row, then file); files under the media root older than 24 h without a row (and stale `*.tmp`) are deleted; counts are logged. ## Post lifecycle

`draft -> pending_approval -> approved -> scheduled -> publishing -> published | failed`

- Without required approval: `draft -> scheduled` (or `publishing` for "publish now").
- Rejected: `pending_approval -> draft`. Edit after approval: `approved|scheduled -> draft`.
- Manual retry: `failed -> scheduled`. `published` is final.
- Source of truth: `src/backend/heardloop/domain/workflow.py`.
